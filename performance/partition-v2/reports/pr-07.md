Every newly enabled core case improved in the original matrix run (4.065x–4.089x). Initially flagged controls were repeated in balanced parent/child order, four fresh runs per library and 101 samples per case; five difficult controls received eight runs. Repeated point estimates span 0.874x–1.072x. Initial matrix readings are retained above rather than substituted with selected reruns.

**Control variability and follow-up:** two unchanged-path default-clock controls were bimodal. The 100%-null fixed-width run-median point estimate was 0.874x (bootstrap interval about 0.664x–1.005x); a nullable one-column fixed-width control was 0.967x (0.817x–1.068x). Neither interval establishes a regression. All 577 shared GPU kernels have identical SASS instructions before and after this addition. A separate four-run balanced diagnostic with SM clocks matched at 2040 MHz gave 1.375x and 1.211x, respectively (the third null-STRING control was 1.428x). These unchanged-path positive readings are not attributed to this optimization. Default clock settings were restored after the diagnostic. Both sets of readings are retained to disclose variability; this is not a universal zero-regression guarantee.

The supplemental 18-case matrix covers 1M/4M/8M/10M rows, maximum string lengths 32/128/512 bytes, uniform/90%-hot maps and sliced inputs, with 21 samples each. Twelve cases enable the new large-input path; all improved. The 512-byte largest fixture uses 8,000,003 rows to stay within the native test wrapper's INT32 column-size limit.
